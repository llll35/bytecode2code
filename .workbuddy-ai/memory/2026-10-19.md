## 修复：`_drop_dead_tail` 增加「丢弃死尾裸 return」

**缺陷**：`def f(...): return a < b < c < d < e < g` 反编译成
`return a<...<g` 后再多一条裸 `return`（不可达）。链式比较的最终跳转落到函数隐式
`return None` 尾声，被当成独立语句发射。
**修复**：`bytecode2code/decompiler.py` 的 `_drop_dead_tail` 增加一段：当末尾是
裸 `ast.Return(value=None)` 且其前一条是 Return/Raise/Break/Continue 时丢弃（不可达）。
仅在两处函数体调用点生效。
**结果**：longchain 3.9/3.10/3.12 通过（3.11 本已通过）；广谱 22→19。controlflow
矩阵逐项一致（32 不变，无回归）。selftest 待复跑确认。

## 关键结论：大量「失败」其实是字节码不可区分（非缺陷）

排查后确认以下广谱失败属**编译期信息丢失 / 字节码歧义**，无法在不破坏其它用例的前提下复原：
- `except_as` / `exceptions`：函数末尾显式 `return None` 与隐式尾声字节码相同；
  反编译选择省略（若发射会污染所有无显式 return 的函数）。
- `whileelse`：`while ... else` 无 `break` 时，else 与循环后代码字节码相同。
- `retfinally` 3.10+：`return y` 是死代码，3.10+ 编译期已删。
- `d4_else_in_loop` / `d4_else_with_break`：`except E: pass` 与 `except E: continue`
  字节码相同（空体+跳回循环头）；且 else 与 handler 回边都指向循环头。
- D2 系列多属 break/continue 回边歧义。

**仍可修（真实缺陷，尚未动）**：
